Security

What our plugins actually touch, what they never send anywhere, how to report a vulnerability, and an honest answer on formal certification — not a compliance page written to sound reassuring.

How these plugins are built

Every plugin in this catalog runs as a normal IntelliJ Platform extension: inspections, annotators, and intentions that execute inside your own IDE process, on your own machine, using the IDE's own PsiElement/AST APIs or plain text/regex checks over files already open in your project.

There is no Gap Hunter Labs backend. We don't operate a server that plugin code calls out to — there's nothing to send your source to, because nothing was built to send it anywhere. Detection logic (pattern matching, entropy checks, structural analysis) runs locally and its output goes straight to the editor: a warning, a gutter icon, a quick-fix. That's the full round trip.

Network activity

  • Plugin installation and update checks go through JetBrains' own Marketplace infrastructure — the same channel every plugin on the platform uses, not something we operate.
  • A small number of plugins call an external API by design because that's the plugin's stated job (for example, a spec-validation plugin that checks a schema against a public registry). Each of those calls goes to the third-party service the plugin's own listing names, never to us.
  • This marketing site (the one you're reading now) uses GoatCounter for visit counts — cookie-free, no IP address stored, sessions rather than raw pageviews. See Methodology for the exact wording. This has nothing to do with what plugins do inside your IDE.

Open by default

Every plugin's source is a public repository under github.com/GapHunterLabs. Nothing described above is a promise you have to take on faith — the inspection/annotator code that decides what runs and what it does with a match is readable in full, plugin by plugin.

Reporting a vulnerability

Found something real — a plugin doing more than its listing says, an insecure default, a dependency with a known CVE we haven't picked up yet? Email gaphunterlabs@gmail.com with the plugin name/version and repro steps. We aim to acknowledge within 5 business days, the same response window we hold ourselves to on outbound disclosures to other maintainers.

Please don't open a public GitHub issue for a security report until we've had a chance to respond — everything else (bugs, feature requests) is fine in the open as usual.

What we don't have (yet)

Gap Hunter Labs does not hold a SOC 2, ISO 27001, or any other third-party security certification. We're a small, focused catalog, not a company with a dedicated compliance team, and we'd rather say that plainly than imply a level of formal assurance that isn't there.

The sections above describe our actual architecture and practice, not a substitute for certification — if your organization's procurement process requires SOC 2 specifically, that's a real gap today, not a checkbox we're quietly skipping.
